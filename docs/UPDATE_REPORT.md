# NORDA 2.8.0 update report

This release builds directly on the latest `Norda-Main-v2.7.0.zip` and implements courier/delivery tracking, transactional order/payment email and independent size/color SKU variants.

Customers now open Track delivery from My Orders. Administrators assign courier name/number/HTTPS link, dispatch and record delivery progress with public notes. Append-only events retain server timestamps, request replay and pagination; customer responses exclude administrator metadata. Existing paid-state, fulfillment and cancellation/refund guards still apply. The prior basic status controls remain usable and create shipped/delivered history. Courier updates are store-entered; carrier booking, rates, polling/webhooks and label creation are future integrations.

Order confirmation, payment changes, shipping, delivery, cancellation and shipment-progress notices are stored in a durable outbox using the existing SMTP configuration. Messages remain held until the commerce operation commits. Atomic delivery claims, five bounded retries, stable Message-ID and interrupted-worker recovery support background delivery without performing SMTP inside checkout/payment/database transactions. Admin Email notifications shows status/redacted errors and retries failed mail. Local `mail:orders` previews are separate from account reset/verification previews. SMTP acceptance does not guarantee inbox placement; ambiguous interruptions can still produce duplicate emails at the provider boundary.

Products support up to 50 retained size/color options with unique SKU, individual prices/discounts/photos and independent stock. The selected option survives guest login, separate cart lines, checkout/invoice snapshots, cancellation, reservation expiry/retry, review recovery and physical return restocking. Shared atomic inventory writes change the chosen SKU and total together; stale admin edits conflict. Existing SKU/size/color identity stays fixed, while price/photos/stock/availability remain editable. Existing ordered simple products cannot be converted in place; create a new variant product. Existing catalog entries are not auto-converted or reseeded.

The database URI, JWT/admin/gateway/SMTP credentials and input `.env` are preserved byte-for-byte. No dependency version is added, removed or upgraded. Existing seed/catalog photos, branding, base CSS, auth/account-recovery/address-book source and unrelated configuration are retained. Related order/cart/catalog/mail handlers are extended for these features, with all prior default and native journeys passing. No baseline source file is deleted and no owner database or real merchant/inbox is used in preparation.

Verification: 159 JavaScript syntax checks; 292 default passes, zero failures and six opt-in native entry points skipped without a test URI; 87 native passes on standalone MongoDB and 87 on a replica set, including the database-level unique SKU race. An isolated SMTP listener accepts account and order messages with stable Message-ID. Actual server startup, variant checkout, automatic private-preview order email with invoice reference and graceful shutdown pass on a separate isolated MongoDB. Current dependency audit reports zero vulnerabilities.

Apply the source while retaining working `.env`, later laptop-only SMTP settings, uploads and Git history. Run `npm ci`, `npm run verify`, `npm run dev` from `server/`; no setup, reseed/manual migration or new credentials are required.
