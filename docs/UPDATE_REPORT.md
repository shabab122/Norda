# NORDA 2.7.0 update report

Based on the latest `Norda-Main-v2.6.0.zip`, this release adds administrator payment review, customer cancellation requests and whole-order returns/refunds.

The new **Requests & payments** workspace shows transaction attempts, reasons, risk, refund progress and private audit notes. Real charges are verified again before a review is approved or refunded. A retained charge can fund fulfillment only when its balance is intact and every additional charge is fully refunded. Risky payments need an explicit acknowledgement. Expired reservations can reopen only after re-reserving stock; manual cancellations remain final. Refunding one charge does not silently resolve a multiple-charge review.

Customers request cancellation before shipment or a whole-order return after paid delivery from My Orders. Administrators approve/reject with a customer-visible message. Pending cancellation blocks fulfillment/payment retry. Approval restores stock once and queues any captured-payment refund; unpaid cancellation completes without inventing a repayment. Return approval alone changes no stock or money: physical receipt and an explicit sellable-stock decision come first, then the remaining refund is queued.

A replay-safe refund ledger caps reserved/completed amounts per bank charge and separates ordinary refunds from additional-charge refunds. SSLCOMMERZ submission uses a unique refund transaction ID and remains pending until a matching provider query confirms `refunded`. The background worker resumes saved eligible records; timeout/interrupted submission requires existing-reference reconciliation and cannot cause a blind resubmission. COD requires actual repayment with a receipt and acknowledgement. Local simulation transfers no real money. Partial monetary refunds are supported after order eligibility; per-item physical returns/exchanges and configurable return windows remain future work.

Order/invoice identity, original items/prices/totals and shipping snapshots remain intact. Refund/return details are synchronized separately; confirmed ordinary refunds reduce net sales, review/simulated funds are excluded and additional refunds do not reduce the retained sale twice. Customer projections omit private audit notes, bank/provider references and session secrets.

All related writes use the existing order lock and transaction/compensation infrastructure. No dependency versions, real credentials, account-recovery/address-book source, catalog/AI photos, shared brand assets or existing base CSS were changed. No baseline file was deleted. Input `server/.env` is preserved byte-for-byte. Keep your laptop's working `.env` (including later SMTP changes) and uploads when applying the update.

Verification: all 142 JavaScript syntax checks passed; 248 default test passes, no failures and 5 native entry points skipped by default; all 69 native tests passed on standalone MongoDB and all 69 on a replica set; the current dependency audit reports zero vulnerabilities. Tests cover real HTTP/Mongoose persistence plus controlled gateway fixtures, races, rollback and frontend account/timeout guards. Actual browser/mobile/print checks and public merchant sandbox/refund settlement require the target environment; no external money was transferred in preparation.

Apply source while retaining working `.env`, Git history and uploads; run `npm ci`, `npm run verify` and `npm run dev` from `server/`. No reseed/manual migration or new secret is required.
