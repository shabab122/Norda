# NORDA 2.5.0 update report

The supplied 2.4.2 source now includes password recovery, email verification and a delivery address book. Customers can request a reset, use an expiring one-use link, set a confirmed password and sign in normally. Successful resets invalidate earlier sessions. New accounts receive verification email; existing accounts can request it from Profile, and verification status is shown without changing established login or shopping permissions.

Profile supports up to 10 labeled addresses with edit/delete/default actions. Old single-address profiles remain accessible without a migration. Checkout has a saved-address selector and retains manual delivery fields. Editing or deleting a saved address does not rewrite earlier orders or invoices. Contact/security saves and address-book edits use separate requests to avoid overwriting another saved address with stale form values.

SMTP support and private development previews are included. With no SMTP host in the supplied configuration, request an account email and use `npm run mail:preview -- your-account@example.com` from `server/` to open its link locally. Real customers receive messages after the owner configures SMTP. Production disables file previews and requires SMTP/TLS and HTTPS account URLs. No merchant, email-provider or other external credentials were invented.

The supplied private `.env` is preserved byte-for-byte, and stays ignored by Git. Existing customer/admin passwords are changed only when their owner intentionally completes a reset or authenticated password change. Existing catalog/seed files, AI images, branding, payment services, stock/order/invoice business logic, reports and reserved-port safeguards remain unchanged. All pre-existing dependency lock entries are identical; Nodemailer is the sole added dependency. No setup, seed, migration or live store database operation was run as part of preparing this update.

Verification: clean `npm ci`; 112 JavaScript syntax checks; 128 default test passes, 0 failures and 3 opt-in native skips; 42 passes against real standalone MongoDB and 42 against a replica set; isolated SMTP protocol delivery and failure tests; dependency audit with 0 vulnerabilities. See [the full results](VERIFICATION_RESULTS.md). External inbox delivery, actual browser/device acceptance and public SSLCOMMERZ validation remain target-environment checks.

Update/run instructions and email settings: [ACCOUNT_RECOVERY.md](ACCOUNT_RECOVERY.md) and [../RUN_COMMANDS.md](../RUN_COMMANDS.md). Keep the existing MongoDB URI and credentials; run `npm ci`, `npm run verify` and `npm run dev`. No reseed is required.
